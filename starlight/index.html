四条通道

有哪个用哪个，失败自动降级

所有操作都是 shell 直写，不做模拟点击、不靠无障碍去点开关。设置页可指定优先级。

Shizuku

装好并启动 Shizuku（或 Stellar）并授权本应用，服务端以 shell 身份 fork sh -c 执行脚本。

无线调试 ADB

Android 11+ 打开「无线调试」，用 6 位配对码与本机 adbd 配对，之后本机直连 shell——不用 root、不用电脑。

电脑 ADB 守护进程 1.39 新增

手机 USB 连电脑、开 USB 调试，电脑跑一行 adb shell sh …/files/start.sh，手机就有 uid=2000(shell) 常驻进程在 127.0.0.1:47901 上等命令——没有无线调试（Android 10 及以下）、也没有 root 时用这条。

Root

有 su 就直接 su -c。四条通道任一失败，自动试下一条。

功能

一键授权、冻结卸载、任意 shell

每项操作写完都在同一段脚本里回读系统真值（appops get / settings get / dumpsys）再判定成功，不信退出码。

一键授权 / 撤销

  • 解除停用 → 可授予的权限（pm grant）
  • 20 项 AppOps（appops set）一次写入
  • 无障碍服务、通知使用权、设备管理员、电池白名单
  • 反向「撤销」同法，详情页还能逐权限开关

应用管理

  • 冻结 / 解冻：禁用、挂起（Android 12+，数据保留）、隐藏、强制停止
  • 卸载 / 恢复：pm uninstall --user 0 与 install-existing，「已卸载」可一键装回
  • 强停、清数据、直接启动

实验台

走当前通道执行任意 shell，输出原样返回。想验证什么系统行为，不用再连电脑。

系统级 + 屏幕灰度

通道页可用 Root 生成本应用的 Magisk 模块（含 priv-app 白名单），重启后冻结走系统 API、不依赖 shell； 屏幕灰度用 daltonizer 单色开关，可逆、不改亮度与分辨率。

安全模型

脚本写死，输入过不了命令

怎么防止注入

脚本正文都在 res/raw/*.sh，Kotlin 侧只做两件事：字符集校验（包名只允许 [A-Za-z0-9._]，组件名额外允许 $）+ 占位符替换。用户输入不可能变成任意命令。

唯一的任意命令入口

就是「通道」页的手动命令台——这是显式功能，不是漏洞。你敲什么它跑什么，所以别粘来路不明的脚本。

已知限制

签名级 / 系统专属权限：shell 也无权授予，报告里的 ✕ 属正常。

恢复只对预装应用有效：第三方应用用 --user 0 卸载是真删，恢复不了。

无线调试通道需要 Android 11+，且要求同一个 Wi-Fi 下能连到本机 adbd；Android 10 及以下请走「电脑 ADB 守护进程」或 Root。

冻结的「隐藏 / 挂起」依 ROM 而异，部分深度定制系统会拦或重启后回滚。
